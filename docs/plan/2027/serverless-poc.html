The $20 Control Plane

The production architecture costs $340–540 a month to serve one user. Almost all of it is redundancy and idle capacity — neither of which a pre-revenue product needs. Here is the same architecture, deliberately stripped of both.

What the floor actually buys

The floor is not the cost of running DMaker. It is the cost of never being down. Roughly 75–90% of it is redundancy or capacity kept warm in case someone shows up.

Struck rows are eliminated outright in the POC — not reduced, removed.

Aurora Postgres v2, Multi-AZ $90+ Automatic failover — a standby ACU set doing nothing

Availability and latency are spent. The data model, the tenancy boundary, and the interfaces are not.

That second clause is the entire discipline here. A cheap POC that skips org_id or forks the run-event contract is not cheap — it is a rewrite with a discount.

The one hard constraint

Blocking

Lambda's maximum execution time is 15 minutes. A DMaker run is 20–30 minutes of agent work. "Lambda only" therefore cannot mean "the agent runs in Lambda." The control plane fits Lambda comfortably; the execution plane does not, and no amount of tuning changes that.

There are exactly two ways out, and the POC takes the first.

1. The hybrid runner — DMaker Connect (D3). Runs execute on the user's own machine, dialling home over the same event contract. Compute cost to us: $0, and personal Claude subscriptions stay legal, which they cannot be on hosted execution. This is not a POC hack — it is verbatim the plan's own P1: "earliest sellable… cloud execution not required yet — users bring compute."

2. Lambda MicroVMs (June 2026) — 8h ceiling, suspend/resume, snapshots, marketed explicitly for AI coding sandboxes. The AWS-native answer, and already D6's designated POC. But the research appendix flags it young, roughly four regions, and priced only on a third-party read. It stays an optional experiment, never a dependency.

Deferring cloud execution deletes far more than the sandbox bill. It deletes four whole services — the LLM gateway, the git proxy, the egress proxy and the sandbox cluster — because every one of them exists to contain untrusted code running on our hardware. That is why the POC is 20× cheaper rather than 2× cheaper.

Worth stating plainly: going serverless does not cost you most of your availability. Lambda, API Gateway, S3, DynamoDB, SQS and SES are regional services with AZ redundancy included at the same price. The only genuine single-AZ decision in this entire document is Aurora. "No availability" is really a description of the database — and of the fact that nobody is on call.

The trap that doubles this bill

Do not add a keep-warm ping. The obvious fix for cold starts is a 5-minute EventBridge tick against λ api. It costs ~$0.30/mo in Lambda — and it keeps Aurora permanently awake, taking it from $8 to $43.80 (0.5 ACU × $0.12 × 730h). A $0.30 optimisation buys a $36 regression. If cold start becomes intolerable, put provisioned concurrency on λ api alone and leave the database asleep.

What is deliberately broken

Naming these is the point. Each is a decision with a price, not an oversight.

Broken Consequence Stops being acceptable when
No Multi-AZ An AZ event takes the database, and therefore the product, down until AWS restores it First paying customer, or any uptime commitment in writing
Aurora resume from zero ~15s on the first request after an idle window Two humans use it in the same hour — at which point it stops pausing anyway, so the saving evaporates before the annoyance does
WebSocket: 10-min idle, 2h hard cap A quiet stretch mid-run drops the socket; any session past two hours drops unconditionally Never — engineer around it, don't tolerate it. Heartbeat every ~5 min, reconnect resumes from lastSeq against run_events, terminals use tmux reattach. Production wants all three regardless
No egress proxy, no git proxy Prompt-injection exfiltration mitigations do not exist — which is exactly today's local-product threat model, while execution is on the user's own machine The moment a second tenant's private repo runs on our compute. Hard gate, no exceptions
No LLM gateway No budgets, no metering, no cache-savings visibility, no credit wallet The first platform-billed (non-BYOK) user. Credits cannot ship without it
No Redis Coarse rate limits; replay is a DB read rather than a RAM read Around five concurrent runs, or when WS fan-out gets hot
Tick-driven scheduler Transitions nothing else triggers wait up to 5 minutes Already mitigated: SQS handles immediate transitions, the tick is only the watchdog
Nobody on call Recovery time is "when Dylan wakes up" Self-evident

The reversibility contract

The POC is allowed to be cheap only where the cheapness sits behind an interface. Everything on the left costs nothing today and is brutal to retrofit, so it ships at full production fidelity from the first commit.

Production-grade from day one

Free now. A migration of every table and every query later.

  • org_id on every row, RLS policies, SET LOCAL app.org_id inside every transaction — the entire tenancy boundary
  • The tenant directory (org → shard). One shard today; the lookup is free, the retrofit is not
  • Storage-driver interfaces and Postgres drivers
  • The SandboxProvider seam — no implementation behind it is fine, no seam is not
  • The GitHostProvider abstraction
  • Run FSM, the 60-event contract, per-event seq numbers — fork these and you fork the client
  • Better Auth and orgs from the first sign-in
  • Envelope-encrypted credentials and audit_log — impossible to backfill honestly

Permitted to be POC-grade

Each is a swap behind something on the left.

  • Multi-AZ and failover
  • Redis / ElastiCache
  • The LLM gateway (LiteLLM)
  • The git proxy and egress proxy
  • The sandbox implementation itself
  • WAF
  • Warm pools and provisioned concurrency
  • The admin console

Phases

POC-0~2 weeks

Prove the four cheap seams

Each is a load-bearing cost assumption above, and each is half a day to falsify. Aurora at min 0 ACU over the Data API with RLS — confirm SET LOCAL holds across Data API calls in one transaction, because if it doesn't, the whole no-VPC saving collapses and we fall back to Lambda-in-VPC at +$22/mo. Express 5 under Lambda Web Adapter — confirms this is a deployment change, not a rewrite. WebSocket reconnect-resume — kill the socket mid-run, replay from lastSeq, no gap and no duplicate. Cost telemetry — a $40 budget alarm on day one, because the failure mode of every serverless POC is a bill nobody read.

POC-1~4 weeks

Control plane live, hybrid runner — and this is sellable

Deploy the stack; sign-in via Google, Microsoft and email; repo connect through the GitHub App; runner v2 — dial-home job protocol plus the runner-RPC surface covering worktree, git, diffs, attachments and logs. The plan is explicit that this RPC surface, not the transport flip, is the bulk of the work. Owner-only dispatch. Cloud execution absent by design. Revenue is seats.

POC-2optional

One Lambda MicroVM sandbox

Single-tenant, own repo, BYOK, behind SandboxProvider. Its purpose is not to serve customers — it is to settle D6's three open questions before production commits to them: does suspend/resume actually work, is the ~$0.10/vCPU-hr read real, and are the regions there? Answering that for ~$7/mo beats answering it inside a production migration.

Graduation triggers

The POC ends and the production plan resumes as written at the first of these, whichever arrives.

Trigger Why it's the line
Second paying tenant Pooled multi-tenancy with real money on it needs Multi-AZ, WAF and someone on call
Any customer repo on our compute Egress proxy, git proxy and no-task-role become mandatory the same day. Non-negotiable
First platform-billed user Requires the LLM gateway, budgets, metering and the credit wallet
≥5 concurrent runs, or Aurora stops pausing The saving has already evaporated; provisioned capacity is now cheaper and faster
WebSocket spend past ~$20/mo Per-message billing has crossed a resident gateway's cost. Chatty agent output at 100–200ms cadence makes this the likeliest cost surprise in the model
Any written uptime commitment An SLA you cannot survive an AZ event for is a liability, not a sales asset

Because the reversibility contract holds, graduating is a deployment change plus four service builds — the LLM gateway, the git proxy, the egress proxy and the sandbox implementation. Not a re-architecture. That is the return on the discipline.
